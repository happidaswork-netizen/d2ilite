## 1. 产品定位

**D2I Cloud 是主产品。**  
部署在 NAS 上，提供常驻 Web UI + HTTP API + Worker。它负责：

1. 队列运行与状态展示
2. 下载结果预览与落盘路径追踪
3. 原数据 / TITI 元数据查看与人工修正
4. 内建 AI 辅助（提取、整理、视觉体型等）
5. 对 Hermes 与人工暴露统一 CLI/API 契约

**Hermes 是 AI 助手，不是主界面。**  
它通过 D2I 的 CLI/API 工作，重点能力是：

1. 读目标网页/源码 → 检索历史经验 → 生成或修正抓取模板
2. 把本次成功/失败经验写回模板经验库（给下次 AI 用）
3. 用 CLI 开启 / 管理 / 检查 / 修复队列
4. 不替代 D2I Web 看板；不成为唯一控制面

**模板经验库是 AI 的记忆，不是用户日常操作台。**  
用户不会逐站手写选择器；库内存的是可复用的站点模式、模板 JSON、验收口径与踩坑记录，供 Hermes 等 AI 检索与生成。

**TITI 是下游消费侧。**  
读取 D2I 写入的 v2.3 元数据做筛选与生图；不反向成为 D2I 的队列 UI。

```text
用户浏览器 ──► D2I Cloud Web UI（主界面）
                  │
                  ▼
            D2I API + Job DB + Workers
                  │
Hermes ──CLI/API──┘  模板工厂 + 运维助手
                  │
                  ▼
            图片文件 + titi-meta 元数据 ──► TITI
```

## 3. 信息架构（Web UI，学 TITI）

部署形态对齐 TITI：`frontend + FastAPI backend + docker-compose`，NAS 常驻访问。

可复用 TITI 的**交互骨架**，不复用生图业务：

| TITI 参考 | D2I Cloud 对应 |
|-----------|----------------|
| `Queue.vue` 队列总览 / 成功失败 / 重试 | 采集队列台 |
| `HoverImagePreview` 悬停预览 | 结果缩略图预览 |
| 设置页的模型配置 | D2I 内建 AI 渠道配置（与 Hermes 分离） |
| 资产库浏览感 | 批次结果库 + 元数据侧栏 |

### 3.1 页面

1. **队列台 `/queues`**
   - 列表：队列名、模板、状态、进度、成功人数、错误人数、开始/更新时间
   - 操作：启动 / 暂停 / 继续 / 重试失败 / 取消 / 仅重下图片
   - 实时：WebSocket 或短轮询（5s）刷新计数

2. **队列详情 `/queues/:id`**
   - 顶部 KPI：discovered / downloaded / completed / failed / quarantined
   - 中部：结果网格（缩略图）
   - 右侧 / 抽屉：选中项详情
     - 预览大图
     - 来源事实：`people_profile`（姓名、职务、单位、来源 URL…）
     - 视觉审核：`visual_*`（含 `visual_body_type`）
     - 采集信息：`d2i_profile`、模板 id、job id
     - 落盘：最终路径、staging 路径、原始 SHA256、`titi_content_hash`
     - 状态：file_status / archive_decision / 错误原因
   - 底部：任务日志尾部、dead letter / quarantine 列表

3. **结果库 `/library`**
   - 跨队列浏览已成功图片
   - 按姓名 / 单位 / visual_* / 批次筛选
   - 点开同样进入元数据侧栏

4. **设置 `/settings`**
   - 存储卷路径（vol1/3/4）
   - 抓取默认礼貌参数
   - **内建 AI 渠道**（文本补全 + 视觉分类），与 Hermes 配置隔离
   - 鉴权 token（NAS 暴露时必须）

5. **模板经验库（默认不对用户当主页面）**
   - **主消费者是 Hermes / 其他 AI**，不是用户手工「打开模板库点选」
   - 用户日常只给 URL + 范围 + 验收口径；AI 负责勘察、生成、验证、入库
   - Web 侧最多提供只读/排障入口（可选、低优先级）：搜索某域名用过什么、最近失败原因
   - 真正完整能力走 API/CLI：检索相似站、导入模板、写回 run outcome、附经验笔记

### 3.3 模板经验库定位（重要）

模板不是「给人填的网站说明书」，而是 **AI 可检索、可演化的抓取经验记忆**。

```text
用户：给一个新 URL
        │
        ▼
Hermes：检索经验库（同域 / 同 CMS / 同政府门户骨架 / 相似选择器 / 历史速度档）
        │
        ▼
      生成或改编模板（含 speed_tier 建议 + 理由 + crawl 数字）
        → 结构轮/模式轮/准生产轮
        │
        ▼
      队列按模板档位跑（D2I Web 看进度与结果）
        │
        ▼
      写回经验：模板 + 验证摘要 + 成功/失败模式 + 计数 + 实际档/是否冷却
```

经验库至少存四类东西（比「一堆 JSON 模板文件」更完整）：

| 类型 | 内容 | 给 AI 的用途 |
|------|------|----------------|
| 可执行模板 | `scraper/templates/*.json` 契约正文 | 直接启动或改编 |
| 站点指纹 | domain、CMS/门户骨架、是否 JSL/browser、**推荐速度档**、礼貌参数 | 新站相似检索 |
| 验证与验收 | expected/discovered/downloaded/completed、推荐模式、**实际采用档/是否触发冷却** | 避免重复踩坑 |
| 经验笔记 | 选择器为何有效、反爬表现、分页坑、图片命名坑、**为何建议该档** | few-shot / 生成约束 |

**用户不负责**：逐站打开 DevTools 找标签、手写 selector、维护模板目录、逐站手填秒数。  
**用户负责**：提目标 URL/范围、看队列与结果、在必要时批准更高风险档位或处理 quarantine。

### 3.4 速度档：AI 在做模板时就建议

速度档是**模板生成时的一等产出**，不是队列跑起来后再拍脑袋。  
引擎仍用现有 `crawl.*` 数字字段；档是默认包 + 经验标签。

#### 三档（用户可见中文名）

| 档（中文） | 代码枚举 | 页间隔 | 图间隔 | 站点组并发 | 定位 |
|------------|----------|--------|--------|------------|------|
| **安全** | `safe` | 5–15s 抖动 | 2–5s | 1 | **NAS / 敏感站默认** |
| **标准** | `standard` | 3–8s | 2–5s | 1 | 已验证稳定的一般公开站 |
| **极速** | `turbo` | 1–3s（或模板覆盖） | 可更短 | ≤2 且需确认 | 明确低风控；**禁止默认** |

运行时状态（不是人选档，由 worker 自动进入）：

| 状态 | 行为 |
|------|------|
| **降速中** `error_slow` | 出错后 15–35s/页，仍可继续 |
| **冷却中** `cooldown` | 写 `backoff_state`，整站点组停跑 N 小时（沿用 `blocked_backoff_hours`） |

#### AI 生成模板时的强制产出

Hermes / 模板 skill 在交付模板时**必须**给出：

1. `speed_tier_recommended`：`safe` | `standard` | `turbo`
2. `speed_tier_reason`：一两句（域名敏感度、WAF/JSL、历史 outcome、页面体量等）
3. 展开后的 `crawl` 数字（可与档默认一致，或单项覆盖）
4. `speed_tier_requires_user_confirm`：仅当建议 `turbo`（或从安全升到更激进）时为 true

建议写入模板示例：

```json
{
  "crawl": {
    "speed_tier": "safe",
    "speed_tier_reason": "政府门户同域 WAF 风险；经验库同 CMS 均在 safe 下完成",
    "concurrent_requests": 1,
    "interval_min_seconds": 5,
    "interval_max_seconds": 12,
    "image_interval_min_seconds": 2,
    "image_interval_max_seconds": 5,
    "blocked_statuses": [403, 429, 412, 521],
    "blocked_backoff_hours": 6,
    "suspect_block_consecutive_failures": 3
  }
}
```

#### AI 如何选档（启发式，可写进 skill）

| 信号 | 倾向 |
|------|------|
| `.gov.cn` / 政务公开 / 领导之窗 / 已知敏感 | **安全** |
| 经验库同域或同 CMS 曾 cooldown / 高 403 | **安全**，并加长 backoff |
| 普通机构站、历史 standard 稳定 | **标准** |
| 明确无 WAF、小站、用户要求尽快且风险低 | 可建议 **极速**，但必须 `requires_user_confirm` |
| 勘察已见挑战页/验证码/跳首页 | **安全** + 笔记；不得建议极速 |

规则：

1. **默认安全**；拿不准就安全。  
2. 运行中只允许自动变严（→ 降速中 / 冷却中）；变松或选极速要用户/显式确认。  
3. 档是默认包；`interval_*` 等数字仍可覆盖。  
4. 创建队列时继承模板 `speed_tier`；Web/CLI 可覆盖，但升档要留审计。  
5. `templates search` / outcome 必须带回历史档与是否触发过冷却，供下次 AI 复用。

### 3.5 桌面端关系

- `desktop-next` 的 scraper 工作台能力可复用到 Web 的队列台概念层。
- NAS 主入口是 Web；桌面端可继续本地开发/轻量使用，但 API 契约应与 Cloud 一致，避免双轨。

## 4. 内建 AI（与 Hermes 分渠）

### 4.1 原则

1. **渠道独立**：D2I 使用自己的 OpenAI-compatible 配置（文本 + 视觉），不读取 Hermes profile 的密钥全集。
2. **规范唯一**：输出字段必须符合 TITI v2.3；枚举用中文权威值。
3. **分层不覆盖**：
   - 来源事实 → `people_profile` / 顶层事实字段
   - 视觉推断 → `visual_*` / `photo_audit` 相关字段
   - 采集工具信息 → `d2i_profile`
   - 模型原始输出 → `visual_classification_raw` 或 `extensions.vision_model.*`
4. **fail-open**：AI 失败不得丢掉已下载原图与抓取结果。
5. **默认只填空 / 建议态**：整理结果默认写建议或仅补空字段；覆盖已有人工确认值需显式开关。

### 4.2 能力 1：自动提取原数据内容

**输入**：详情页结构化字段、列表页邻接文本、已下载图片现有元数据、文件名。  
**输出（建议写入 `people_profile` / 兼容展示字段）**：

- name / gender（仅当来源明确）
- position / organization / province / city / county_or_district
- biography 摘要（短）
- source_url / image_url
- keywords（清洗后）

**实现起点**：

- `scripts/metadata_ai_cli.py`（suggest / autofill）
- `metadata_manager.suggest_metadata_fill`
- `llm_client.OpenAICompatibleClient`

**规则**：不得编造；不确定留空；页面全文不进图片热路径，全文留 D 层 JSONL/记录。

### 4.3 能力 2：整理原数据

**输入**：已提取的粗糙 profile + raw_fields。  
**输出**：

- 字段归一（性别枚举、行政区划、职务去噪）
- 空字段补全建议
- 冲突标记（来源 gender vs visual_gender 等）
- 可写回的 clean profile patch

**规则**：

- AI 改写默认不能改 `people_profile` 已确认事实、`d2i_profile`、`identity_prompt`，除非用户显式允许。
- 整理结果可先进入 review / suggestion，再由人工或策略应用。

### 4.4 能力 3：直接识别图片体型（及视觉组）

按 TITI v2.3 视觉审核字段一次请求写出：

| 字段 | 枚举（权威） |
|------|----------------|
| `visual_body_type` | `瘦削` / `标准` / `健壮` / `微胖` / `肥胖` / `多人` / `不确定` |
| `visual_gender` | `男` / `女` / `多人混合` / `不确定` |
| `visual_age` | `青年20-30` / `中30-45` / `中年45-55` / `中老55-70` / `老年70+` / `不确定` |
| `visual_pose` | `正面证件照` / `半身侧` / `站立` / `坐姿` / `工作场景` / `合影裁切` / `其他` / `不确定` |
| `visual_attire` | `正装` / `工装` / `便装` / `白大褂` / `制服` / `其他` / `不确定` |
| `visual_hairstyle` | `光头` / `秃头` / `平头` / `短发` / `背头` / `偏分` / `中长发` / `盘发-扎发` / `长发披肩` / `其他` / `多人` / `不确定` |

附加：

- `person_count`（先人数再其余字段；可进 photo_audit / raw）
- `visual_classification_source = vision_model`
- `visual_classification_raw` 保留模型原文
- `visual_warnings` fail-open 警告

**保护与实现约束（合并自 7/16，现行有效）**：

- 每张图**一次**视觉请求；不做双模型复核；不把多图拼成一次请求
- 不同图并发上限 **3**
- 请求前仅内存生成最长边 **1280** JPEG 副本；**不改写原图**
- 请求前后核对原文件 SHA256；若哈希变化 → 立即停视觉任务并回滚相关变更
- 缓存键：源 SHA256 + 模型 + prompt version
- API 失败 **fail-open**：保留原图与下载结果，不阻断整队
- 重跑优先读不可变来源文件（如 `downloads/images/<sha>`）
- 结果写入 `photo_audit` / `visual_*`；**不覆盖** `people_profile.gender` 等来源事实
- `photo_audit.status` 保持待审语义：视觉只是参考，不冒充人工审核结论
- 先 `person_count`，再写其余视觉字段；`person_count=0` 不得被性别规则误判
- **D2I 使用独立视觉 secret**，可从 Hermes 既有 key **复制值**，但**禁止**把整个 Hermes profile 挂进 D2I 容器

**TITI 读取侧（合并自 7/16）**：

- 优先读 canonical `photo_audit.visual_*`
- 兼容 D2I sidecar 顶层 `titi_meta`；旧 `appearance_profile` 只读映射，不写回
- 筛选映射示例：男/女 → male_like/female_like；瘦削→slim；标准→average；健壮/微胖/肥胖→large

## 5. HTTP / CLI 契约（人机与 Hermes 共用）

Base：`/api/v1`  
鉴权：Bearer token（`D2I_WEB_TOKEN`）；本地可关，NAS 暴露必须开。

### 5.1 队列

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/queues` | 列表 + KPI 摘要 |
| POST | `/queues` | 从模板/配置创建并可选立即 start |
| GET | `/queues/{id}` | 详情 + 计数 |
| POST | `/queues/{id}/start` | 启动 |
| POST | `/queues/{id}/pause` | 暂停 |
| POST | `/queues/{id}/resume` | 继续 |
| POST | `/queues/{id}/retry` | 重试失败项；body 可限 scope |
| POST | `/queues/{id}/cancel` | 取消 |
| GET | `/queues/{id}/items` | 结果项分页（含缩略图 URL、状态） |
| GET | `/queues/{id}/items/{item_id}` | 单项：预览、元数据、路径、错误 |
| GET | `/queues/{id}/logs` | 日志尾部 |

### 5.2 模板经验库（AI 主用）

面向 Hermes 的读写记忆面；UI 可不做完整管理页。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/templates` | 列表（可按 domain/tag/cms 过滤） |
| GET | `/templates/search?q=` | **相似经验检索**（域名、CMS、关键词、历史成功率） |
| GET | `/templates/{id}` | 模板正文 + 关联经验笔记 |
| POST | `/templates` | 入库（AI 生成后提交；可含 notes） |
| PATCH | `/templates/{id}` | 更新模板或经验字段 |
| POST | `/templates/validate` | 结构校验 |
| POST | `/templates/{id}/outcomes` | **写回运行结果**：计数、模式、失败类型、是否推荐 |
| POST | `/templates/{id}/queues` | 从已有模板创建队列（AI 或排障用） |

经验检索最低输入：`url` 或 `domain`；可选 `cms_hint`、`need_fields`、`prefer_mode`。  
返回：Top-K 相似模板 + 笔记摘要 + 推荐模式 + 已知风险。

### 5.3 结果库与元数据

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/library` | 跨队列资产筛选 |
| GET | `/assets/{id}` | 资产详情 |
| GET | `/assets/{id}/preview` | 预览图 |
| GET | `/assets/{id}/metadata` | 读 titi-meta / 侧栏结构 |
| PATCH | `/assets/{id}/metadata` | 人工修正（审计） |

### 5.4 内建 AI

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/ai/extract` | 从页面/元数据提取 profile 建议 |
| POST | `/ai/normalize` | 整理/归一 profile 建议 |
| POST | `/ai/vision` | 单图视觉分类（含 body_type） |
| POST | `/queues/{id}/ai/run` | 对队列批量跑 extract/normalize/vision |
| GET | `/ai/jobs/{id}` | AI 子任务状态 |

### 5.5 健康

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/health` | liveness |
| GET | `/status` | worker、磁盘、队列积压、AI 渠道 |

### 5.6 CLI 映射（供 Hermes / 人工）

```text
d2i queues list
d2i queues create --template <id> [--start]
d2i queues start|pause|resume|retry|cancel <queue_id>
d2i queues show <queue_id>
d2i queues items <queue_id> [--status failed]
d2i templates search --url <url> [--domain ...]
d2i templates list|show|validate|import
d2i templates outcome <id> --stats {...} --notes "..."
d2i ai extract --image|--page ...
d2i ai vision --image <path>
d2i ai run --queue <id> --steps extract,normalize,vision
d2i status
```

CLI 只是 HTTP 契约的薄封装；Hermes skill 调同一套，不另开私有协议。  
**Hermes 标准作业顺序**：`templates search` → 生成/改编 → `validate` → `import` → `queues create --start` → 跑完 `templates outcome` 写回。

## 6. 数据与存储（NAS）

沿用既有卷规划，产品侧固定语义：

| 卷 | 用途 |
|----|------|
| `/vol1` SSD | 代码、profiles、脚本、轻量 DB、配置 |
| `/vol3` HDD | 最终图片资产（主库） |
| `/vol4` SSD | runtime、job DB、staging、d2i-jobs、模板工作区 |

核心库建议：

- `jobs.sqlite`：队列、item 状态、AI 子任务
- `people` / assets 索引：与归档 worker 对齐；最终事实服从 TITI v2.3
- 缩略图缓存：独立 cache 目录，可重建

Item 最小状态机：

```text
pending → running → downloaded → metadata_written → vision_done → completed
                 ↘ failed → (retry) → ...
                 ↘ quarantined
```

## 7. Hermes 协作面（助手模式 + 经验写回）

### 7.1 Hermes 允许

1. 使用 `d2i-lite-template-builder` skill，并**强制先检索经验库**：
   - 输入 URL → `GET /templates/search`
   - 命中高相似：改编旧模板（含继承/重评估速度档），不从零发明
   - 未命中：按 SOP 勘察后新写，并打上站点指纹 + **速度档建议**
2. 产出模板 JSON 时**必须含** `crawl.speed_tier` + `speed_tier_reason` + 展开后的间隔数字 + 简短经验笔记 → `validate` → `POST /templates`
3. 建议 `turbo` 时不得静默开跑：须 `requires_user_confirm` 或用户/CLI 显式确认
4. CLI/API 创建并启动队列、查 KPI、拉 failed、retry、读 `/status`（队列默认继承模板档）
5. 队列结束后 `POST /templates/{id}/outcomes` 写回：
   - 实际计数与验收差异
   - 最终推荐模式 / 备选模式
   - **实际 speed_tier、是否进入 error_slow/cooldown**
   - 失败类型分布（403/空选择器/分页/错图…）
   - 是否建议作为该 domain 的默认模板与默认档
6. Telegram 自然语言汇报——数据仍以 D2I API 为准

### 7.2 Hermes 禁止

1. 把 Telegram 当 D2I 主 UI 替代品
2. 跳过经验检索直接从零写模板（除非 search 明确无命中）
3. 跑完不写 outcome（导致经验无法积累）
4. 直接改生产原图字节绕过 D2I 写入路径
5. 用视觉结果覆盖 `people_profile.gender` 等事实字段
6. 与 D2I 内建 AI 共用密钥挂载整包 Hermes profile

### 7.3 模板/经验交付最低要求（延续 AGENTS.md）

1. 模板路径或 template id
2. 校验文档或 outcome 摘要
3. expected / discovered / downloaded / completed 口径
4. 推荐模式（requests_jsl / browser）与切换条件
5. **推荐速度档**（安全/标准/极速）+ 理由 + 是否需用户确认
6. **经验笔记**：本次学到的选择器/反爬/分页/档位要点（给下次 AI 读）

### 7.4 用户与 AI 的分工再强调

| 谁 | 做 | 不做 |
|----|----|------|
| 用户 | 给 URL/范围/验收；看队列与图片结果；处理待审；确认极速档 | 逐站分析 DOM、手填间隔秒数、手维护模板库 |
| Hermes | 检索经验、生成模板（含档位建议）、跑通小样、写回经验与实际档、管队列 | 替用户当结果验收主界面；静默对敏感站开极速 |
| D2I Web | 队列/预览/元数据/内建 AI；展示当前档与冷却状态 | 不强迫用户进模板管理页 |

## 8. 可靠性目标（合并自 7/23，归属 D2I Cloud）

以下工作**仍然要做**，归属 **D2I Cloud 产品可靠性**，不是「让 Hermes 当唯一主控」。细节 checklist 原件见已降级的 7/23 文档；以本节语义为准。

| 阶段 | 含义 | 关键点 |
|------|------|--------|
| Phase 0 | 解卡，保证能写完批次 | 模型/cron/压缩；坏批次 sentinel/回填 |
| Phase 1 | 重启自愈 + 可见 | **flock 替 PID lock**（7/16 换机事故根因）；Telegram/网络可达；`/status` + heartbeat |
| Phase 2 | 数据与磁盘 | micro-batch + quarantine；vol3 治理；日报 |
| Phase 3 | 自动化 | work queue、背压、circuit breaker、审批阶梯 |

已知实现线索（保留，便于施工）：

- 现有 `crawl.*` 间隔/blocked/backoff、`manual_pause.flag`、`backoff_state.json` 已在 d2ilite 公共抓取链路
- 容器重建 PID 复用导致 stale lock：必须 flock 或等价内核锁，不能只靠 PID 文件
- 桥接网络容器内 `127.0.0.1` 不是宿主机；出站服务用 host 网络或 `host.docker.internal`

产品实现顺序：

1. **契约冻结**（本文，已完成文档合并）
2. **API + Job DB + Worker headless 稳定**
3. **Web 队列台 + 预览/元数据侧栏**
4. **内建 AI 三件套** + 独立 secret
5. **Hermes CLI / 模板 skill**（search → tier → validate → import → outcome）
6. **可靠性 Phase 1–3** 并入发布节奏

## 10. 验收口径（MVP）

- [ ] Hermes 对新 URL 会先 `templates search` 再生成/改编
- [ ] 生成模板时输出 `speed_tier` + 理由，并展开 `crawl` 数字

- [ ] 用户仍以 Web 队列/结果为日常主界面，不依赖模板管理页

### MVP-4 可靠性底线

- [ ] worker 重启三次可自愈（flock）
- [ ] 坏记录进 quarantine，不毒杀整批
