# Desktop Next 旧版归档清单（2026-06-27）

适用分支：`feature/tauri-modernization`

## 当前结论

`desktop-next` 已经是后续主线。旧版 `app.py` 暂时只作为规格基线和应急入口保留，不再作为新功能主入口。

旧版可以真正归档前，需要确认下面两类事项：

1. 新版已经承接日常主路径。
2. 未迁移的旧版能力要么搬完，要么明确废弃。

## 已迁入新版

1. 图片目录浏览、当前图片预览。
2. 上一张 / 下一张。
3. 系统打开当前文件、打开所在文件夹。
4. 单图元数据读取、结构化编辑、保存。
5. Profile / TITI / XMP / EXIF / IPTC / Match 原始元数据查看。
6. 原角色名、扮演角色结构化编辑。
7. 目录级角色筛选、勾选与批量编辑。
8. 公共抓取新任务启动。
9. 公共抓取模板枚举、任务配置生成。
10. 公共抓取任务列表、监控、进度表、日志尾部。
11. 已有抓取任务 pause / continue / retry / rewrite。
12. 当前图片加名字白条。
13. 当前图片重命名。
14. 单图 AI 自动补全入口。
15. 元数据补全输入范围：只读文件名、只读当前元数据、文件名 + 元数据。
16. 单图 AI 自动小传入口。
17. 全局设置页：LLM 配置、名字白条默认参数。
18. 抓取复核队列最小工作流：显示 `raw/review_queue.jsonl`、打开/定位本地图片、移出已处理条目，并刷新任务统计。

## 本轮新增

1. `desktop-next` 预览区新增“当前图片工具”。
2. 支持手动输入名字、输出格式、命名方式、输出目录后生成名字白条。
3. 支持直接重命名当前图片，保留原扩展名并自动避免重名。
4. 生成到同目录时，新文件会补进当前图片列表。
5. 修复 `scripts/image_action_cli.py` 直接调用时找不到仓库根模块的问题。
6. Vite dev bridge 和 Tauri bridge 都接入了名字白条、重命名、系统打开、定位文件。
7. 新增 `scripts/metadata_ai_cli.py`，供新版在无 Tk UI 的情况下调用单图 AI 补全。
8. 新版编辑区新增 AI 自动补全工具条，并支持“只读文件名”输入模式。
9. 新增 `scripts/settings_cli.py`，新版可读取/保存 `~/.d2ilite/settings.json`。
10. 新版编辑区新增 AI 自动小传按钮，结果写入描述字段。
11. 新版顶部新增全局设置面板，覆盖 LLM 和名字白条常用参数。
12. 新版抓取监控新增“待复核队列”，支持从复核条目跳转到图片元数据工作台。
13. 新增 `review-clear` bridge 动作，开发桥接和 Tauri 桥接都支持移出复核队列条目。

## 旧版仍待处理

这些是归档 `app.py` 前必须拍板的剩余项：

1. 复核 / 审计增强：新版已有最小复核队列闭环；旧版“打开条目后自动同步审计提示”的自动化逻辑仍可后续增强。
2. 下载修复：旧版有从原图链接直连修复、浏览器修复、替换当前文件并保留元数据的链路。新版尚未迁入。
3. 高级原始元数据写入：旧版可以直接编辑 XMP / EXIF / IPTC JSON 并写回。新版当前以结构化写入为主，原始视图是查看。
4. 批量下载器旧入口：旧版仍能打开 `legacy_downloader_gui.py`。是否继续保留需要单独决定。
5. 默认图片打开软件 / 文件关联：已有脚本支持 EXE 注册，但新版正式 exe 和启动参数接入还要完成后再设置。
6. 正式发布包：调试构建链路存在，但最终 exe/installer 还需要解决 Python 图片动作/AI/settings sidecar 或改写问题。

## 归档门槛

建议满足以下条件后再把旧版移出视线：

1. 通过 `scripts/desktop_next_release_gate.py`，或至少通过当前改动影响范围内的 `lint/build/smoke/cargo check`。
2. 用户确认新版最小复核队列是否已经够用；如不够，再补审计自动同步增强。
3. 用户确认“下载修复 / 高级原始元数据写入 / 旧批量下载器”是迁入新版还是废弃。
4. 生成一个可运行的新版 exe，并验证：
   - 双击 exe 可启动。
   - 打开目录、预览、编辑、保存、重命名、生成白条可用。
   - 如要设为默认图片打开软件，双击图片能把图片路径交给新版。
5. 旧版移动到 `archive/legacy-tk/` 或改为隐藏入口，并在 README 中标注“仅应急回退”。

## 当前建议

不要现在删除 `app.py`。下一步优先做：

1. 下载修复与高级原始元数据写入是否迁移的决策。
2. 新版 exe 调试构建，并验证文件关联启动参数。
3. 如复核队列实际使用仍不顺，再补“打开后自动同步/清理审计提示”的增强。
